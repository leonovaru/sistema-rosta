# Развёртывание в Cloudflare

1. Создать отдельную D1 database с именем `sistema-rosta-db`.
2. Скопировать её ID в `wrangler.toml` вместо `REPLACE_WITH_CLOUDFLARE_D1_DATABASE_ID`.
3. Выполнить `npm install`, затем `npm run db:migrate:remote`. Команда применяет базовую схему и все миграции, включая учёт фактического времени, сохранение результатов делегирования, список шагов задачи, дневные планы, личный календарь, повторяющиеся события, расходы с привязкой к направлениям дохода, долги и обязательные платежи, аналитику вклада направлений.
4. В Cloudflare Pages создать проект из этого GitHub-репозитория.
5. Build command оставить пустой; output directory — `public`.
6. В Settings → Functions → D1 database bindings добавить binding `DB` к созданной базе.
7. В конфигурации уже объявлен Workers AI binding `AI` с моделью `@cf/google/gemma-4-26b-a4b-it`. Проверь, что он появился в Cloudflare Pages → Settings → Bindings и включён для проекта. Если Cloudflare запросит подтверждение, добавь Workers AI binding вручную. Без него оценщик использует алгоритмический резерв, а выполнение задач ИИ будет недоступно.
8. Не задавать `ALLOW_REGISTRATION=true` для личного режима. По умолчанию разрешено создать только первый аккаунт; после этого регистрация автоматически закрывается.
9. Проверить регистрацию, вход, выход, создание задач, оценку времени, сохранение фактического времени, делегирование ИИ, повторное открытие сохранённого результата, создание/редактирование событий календаря, ежедневные и еженедельные повторения, финансовые операции, погашение долгов, отметку оплаты обязательств и изоляцию данных.

## Режим тестирования

Для будущей бета-версии можно добавить переменную окружения Pages `ALLOW_REGISTRATION=true`. Это откроет регистрацию всем посетителям, поэтому включать её следует только вместе с ограничением доступа/приглашениями и после усиления защиты.

До публичного запуска добавить rate limiting для регистрации/входа, подтверждение email, сброс пароля, CSRF-проверку для изменяющих запросов, политику конфиденциальности и юридические документы. Не использовать реальную базу с тестовыми или публичными демонстрационными аккаунтами.

Текущий код — ранний MVP, а не готовый публичный SaaS. Не публиковать реальные пользовательские данные и не подключать production-базу до завершения проверок.


## Дополнительные миграции и уведомления

После проверки текущей истории D1 применить все ожидающие миграции, включая `0034_sleep_sessions.sql`, `0035_push_notifications.sql`, `0036_sleep_event_timezones.sql` и `0037_sleep_target.sql`. Команда `npm run db:migrate:remote` может применить все ожидающие миграции проекта, а не только перечисленные. Сначала проверь список и историю миграций; не выполняй её повторно вслепую.

Утренние push-уведомления отправляет отдельный Cloudflare Worker. Его настройка, генерация VAPID-ключей, переменные/секреты, D1 binding и cron описаны в `docs/features/push-notifications-setup.md`. Настройка Pages сама по себе не включает push. После настройки требуется реальная end-to-end проверка на телефоне.

Сон и индивидуальная цель сна не считаются запущенными в production до применения миграций 0034–0037. Не включать пользовательский доступ к функциям, пока миграции и права доступа не проверены.
