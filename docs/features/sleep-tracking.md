# Учёт сна и восстановление

## Цель

Добавить в «Систему роста» отдельный модуль «Сон и восстановление», связанный с календарём и утренним подтверждением пробуждения. Модуль наблюдает за фактическим режимом, не превращая расписание в обязательство и не оценивая пользователя.

## Принцип достоверности

Последняя активность в приложении или отсутствие активности телефона не считаются доказательством сна. Веб-приложение не может надёжно видеть, когда пользователь выключил экран или перестал пользоваться другими приложениями. Такие сигналы могут быть только вспомогательными и не должны автоматически записываться как факт засыпания.

Каждое время сна хранится вместе с источником и уровнем достоверности. Неизвестные значения остаются пустыми; система не придумывает время засыпания.

## Модель одной ночи

Одна запись соответствует периоду сна, заканчивающемуся в конкретную локальную дату пробуждения.

Поля:
- локальная дата пробуждения;
- часовой пояс, действовавший для записи;
- время «легла» (необязательное, ручная отметка);
- предполагаемое время засыпания (необязательное);
- время пробуждения (из подтверждения утром или ручного ввода);
- источник каждого значения: ручная отметка, подтверждение в приложении, push-уведомление, интеграция с платформой;
- достоверность: точное время отметки, приблизительная оценка или импортированные данные;
- заметка (необязательно).

Не следует считать время «легла» временем засыпания. Не следует считать время последней активности приложения временем «легла».

## Первая версия

1. Вечером доступно необязательное действие «Ложусь спать»; оно записывает фактическое время нажатия как время отхода ко сну.
2. Утреннее подтверждение пробуждения использует уже согласованное уведомление в 06:00 по часовому поясу пользователя. Нажатие может произойти позже; записывается реальное время нажатия.
3. Если время отхода ко сну не было отмечено, запись пробуждения всё равно сохраняется, а время засыпания остаётся неизвестным.
4. Пользователь может вручную уточнить предполагаемое время засыпания и исправить ошибочную запись.
5. Если push недоступен или пропущен, остаётся действие подтверждения пробуждения внутри приложения.
6. Повторное нажатие в тот же локальный день не создаёт дубликат записи; пользователь может явно отредактировать запись.
7. Никаких автоматических повторных уведомлений без отдельного решения пользователя.

## Статистика

Показывать только показатели, для которых достаточно данных:
- продолжительность сна — только когда известны начало/оценка засыпания и пробуждение;
- средняя продолжительность за выбранный период;
- среднее время отхода ко сну и пробуждения;
- регулярность режима;
- динамика по дням.

Разделять точные отметки и приблизительные оценки. Не рассчитывать «недосып» без заданной пользователем цели сна; целевую продолжительность сна можно добавить в настройках позже. Не делать выводов о качестве сна по одной лишь длительности.

## Интеграции — следующий этап

- iPhone: импорт данных из Apple Health возможен только через совместимое приложение/нативный мост с разрешением пользователя. Обычная веб-страница не получает прямого доступа к Apple Health.
- Android: возможная интеграция через Health Connect и совместимое приложение/мост с разрешением пользователя.
- Системные сигналы активности телефона не использовать как единственный источник сна.

Интеграции не входят в первую версию и не должны блокировать ручной учёт.

## Связь с другими модулями

- Календарь: отображать подтверждённые интервалы сна как фактические события или агрегированные данные, не создавая дублирующих событий.
- Утреннее подтверждение: единый источник времени пробуждения; отдельная запись сна должна ссылаться на подтверждение, а не создавать второй независимый факт.
- Планирование: учитывать сон как контекст восстановления, но не уменьшать рабочую ёмкость автоматически без отдельного решения пользователя.

## Приватность и контроль

- Данные принадлежат аккаунту пользователя и доступны только после авторизации.
- У пользователя есть просмотр, исправление и удаление записей.
- Никакой отправки данных о сне во внешние AI-сервисы.
- Push-уведомления не являются будильником и не гарантируют пробуждение.

## Статус реализации первой версии

В ветке `feature/clients-projects-life-areas` реализовано:
- таблица `sleep_sessions` с уникальностью записи на пользователя и дату начала ночи;
- авторизованный API `/api/sleep`: просмотр последних записей, отметки «Ложусь спать» и «Уже уснула», подтверждение пробуждения, исправление и удаление;
- пробуждение связывается с незакрытой записью текущей или предыдущей локальной даты; повторное подтверждение не перезаписывает уже сохранённое время;
- интерфейс с быстрыми отметками и историей последних 14 ночей;
- ручное исправление времени и заметки;
- продолжительность рассчитывается только при наличии обоих времён (засыпание и пробуждение).

Пока не реализовано:
- автоматическая отправка push и обработка действия из системного уведомления;
- автоматическое объединение с подтверждением пробуждения из отдельного push-модуля;
- импорт из Apple Health / Health Connect;
- расширенная аналитика регулярности и целевого сна;
- автоматическое создание событий сна в календаре.

До подключения push кнопка «Я проснулась» внутри приложения является самостоятельным способом фиксации пробуждения. Миграцию D1 необходимо применить перед использованием API в развернутой среде.
