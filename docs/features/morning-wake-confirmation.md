# Утреннее подтверждение пробуждения

## Зафиксированное поведение
- Ежедневное push-уведомление отправляется в 06:00 по часовому поясу пользователя (начальное значение настроек — Europe/Moscow).
- Текст: «Доброе утро! Ты уже проснулась?».
- Основное действие в уведомлении: «Да, я проснулась».
- Время фактического пробуждения — timestamp нажатия пользователем кнопки, а не время отправки уведомления.
- Подтверждение можно сделать в любое время после 06:00 в течение текущего календарного дня; поздний ответ (например, в 12:00) допустим и записывается как 12:00.
- Пока пользователь не подтвердил пробуждение, состояние дня — «Ожидает подтверждения».
- Не отправлять повторные напоминания автоматически: пока пользователь этого не просил.
- Если уведомление было смахнуто, закрыто ОС или недоступно, на главном экране приложения должно оставаться действие «Подтвердить пробуждение» для текущего дня.
- Повторное нажатие не должно создавать вторую запись за тот же день; допускается отдельный механизм исправления времени, если пользователь ошибся.

## Данные и аналитика
- Хранить дату локального дня, timezone, время отправки уведомления, время подтверждения и источник подтверждения (push или приложение).
- В аналитике различать запланированное время уведомления (06:00) и фактическое время пробуждения.
- Не считать пользователя проснувшимся автоматически в 06:00.
- Если подтверждение не поступило до конца локального дня, день остаётся неподтверждённым; не подставлять фиктивное время пробуждения.

## Технические требования
- В коде ветки добавлены Web Push subscription API, Service Worker, PWA manifest и отдельный Cloudflare Worker с cron каждую минуту. Отправка выполняется в 06:00 локального времени; техническая ошибка повторяется в пределах 10 минут, но успешная доставка за локальный день остаётся одна.
- Действие из push вызывает существующий API сна с источником `push`, затем открывает приложение; время фиксируется сервером при обработке. Интерфейс приложения остаётся резервным способом подтверждения.
- В интерфейсе добавлено включение/отключение push и запрос разрешения; используется часовой пояс из настроек. Подписки хранятся отдельно, endpoint с ответом 404/410 удаляется, уникальность доставки обеспечивается пользователем и локальной датой.
- Для iPhone в интерфейсе добавлена подсказка: сначала установить приложение на экран «Домой», затем разрешить уведомления. Альтернативный экранный сценарий сохранён.
- Уведомление должно оставаться доступным в центре уведомлений до действия пользователя или системного удаления; приложение не должно полагаться только на сохранность системного уведомления — резервное подтверждение обязательно.

## Не входит в первую версию
- Автоматические повторные напоминания.
- Будильник со звуком, гарантированное пробуждение или обход системного режима «Не беспокоить».
- Определение пробуждения по датчикам телефона/часам.

## Статус реализации в ветке

Код добавлен, но отправка ещё не активирована в развернутой среде. Перед запуском нужны миграция `0035_push_notifications.sql`, VAPID-пара ключей, переменная `PUSH_VAPID_PUBLIC_KEY` в Pages и отдельный Worker с D1 binding и cron. Порядок настройки описан в `docs/features/push-notifications-setup.md`. Пока эти шаги не выполнены, приложение не отправляет уведомления; ручная отметка пробуждения остаётся доступной.
