# Утренние push-уведомления — техническая настройка

## Что добавлено в репозиторий
- PWA manifest и Service Worker.
- API для регистрации/отзыва Web Push подписки.
- Отдельный Cloudflare Worker с cron каждую минуту. Он отправляет одно уведомление на пользователя и локальную дату, когда в его часовом поясе наступает 06:00.
- Нажатие действия уведомления отправляет подтверждение на существующий API сна с источником `push`; время фиксируется сервером при получении запроса. Экран приложения остаётся резервным способом.

## Что требуется настроить в Cloudflare до отправки
1. Применить миграцию `0035_push_notifications.sql` к той же D1 базе, которая используется Pages-приложением.
2. Сгенерировать пару VAPID P-256 ключей. Публичный ключ — base64url без padding, приватный — 32-байтовый raw P-256 scalar в base64url. Не использовать PEM и не публиковать приватный ключ.
3. В Pages project variables добавить `PUSH_VAPID_PUBLIC_KEY`.
4. Для отдельного Worker указать тот же D1 database ID в `wrangler.push.toml`, добавить секреты `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, переменную `VAPID_SUBJECT` (валидный mailto или https URL), затем развернуть Worker с cron trigger.
5. В `wrangler.push.toml` заменить placeholder database ID на фактический ID D1. ID намеренно не придумывается и не извлекается из репозитория.
6. Проверить подписку на HTTPS-адресе приложения и сделать контрольную отправку в тестовом окружении.

## Важные ограничения
- Само наличие Service Worker не означает, что push уже отправляется. Пока миграция, VAPID-переменные и отдельный Worker не настроены и не развернуты, кнопка подписки должна сообщать о недоступности.
- На iPhone web push требует установленного приложения на экран «Домой» и выданного разрешения. Поддержка зависит от версии iOS.
- Системные настройки уведомлений и режим «Не беспокоить» имеют приоритет. Это не звуковой будильник и не гарантия пробуждения.
- Push endpoint может истечь или быть отозван; невалидные endpoints удаляются после ответов 404/410.
